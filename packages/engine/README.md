## Движок замкнутого рынка (MODEL-V4)

Запуск приёмочного теста: `npm test` — должно быть **PASS 20, FAIL 0**.

## Что это

Рынок на N участников с фиксированным совокупным капиталом `C`. Цена
формируется только действиями участников. Внешней ликвидности, скрытого
маркет-мейкера и бесконечного пула нет.

## Модель в трёх формулах

```
p(Q) = P0 * (1 + beta*tanh(Q/kappa))        цена состояния (mark)
R(Q) = P0 * [Q + beta*kappa*ln cosh(Q/kappa)]   резерв = интеграл p
P*   = (R(Q+dQ) - R(Q)) / dQ                цена клиринга тика
```

`P*` — **единственная** цена, совместимая с сохранением капитала: собранные
деньги `dQ*P*` в точности равны изменению резерва. Выводится из сохранения и
не зависит от вида кривой.

## Почему именно эта кривая

- **Ограничена с обеих сторон** `[25, 175]` → убыток обеих сторон конечен →
  `equity >= 0` структурно, **ликвидации не нужны**.
- **`R(Q)` в замкнутой форме** → цена клиринга точна. У мультипликативно
  симметричной `exp(tanh)` замкнутой формы нет, и сохранение капитала стало
  бы приближённым.
- **`kappa = C/(P0*THETA)`** → движение цены зависит только от ДОЛИ
  совокупного капитала. Проверено на N = 3…1000 и капитале $100…$10000:
  идентично до 6-го знака.

## Три величины, которые нельзя смешивать

| | что это |
|---|---|
| `mark` | цена рынка, для графика |
| `closeValue` | сколько игрок получит, если ВСЕ закроются в этом тике |
| `PnL` | `closeValue` минус вложенное |

`units * mark` **не является суммой денег** и не отдаётся в снапшоте.
`Σ closeValue = escrow` тождественно, поэтому `Σ equity = C`.

## Ключевые свойства (все проверены в test/audit.js)

- сохранение капитала: дрейф ≤ 7.3e-12 на 20 сессиях × 400 тиков
- порядок заявок в тике не влияет ни на что: ΔP = 0.0e+0
- самораскачка даёт ровно 0 (телескопирование `R`)
- одновременный выход: разброс выплат 0.0e+0
- пассивный игрок: Δequity = 0.0e+0 при любой активности других
- без сделок цена стоит: 100.0000000000 за 1000 тиков
- симметрия: `mark(long) + mark(short) = 200.000000`

## Чего движок НЕ гарантирует

**Показанный `closeValue` не защищён от действий других.** Если выходить по
одному, первый получает +4.50, последний −4.59 (сумма 0). Это price impact,
и он неустраним: гарантировать показанное значение при том, что цена зависит
от действий участников, математически невозможно (доказано в FINAL-AUDIT-V3).

Следствие для UI: `closeValue` обязан обновляться в реальном времени и
подаваться как «сейчас», а не как обещание.

**Потолок доходности ±75%.** Следствие ограниченности кривой. 10x за сессию
невозможен без плеча, а плечо разрушит `equity >= 0`.

## Состав

```
config.js      параметры; каждый обоснован измерением
curve.js       p(Q), R(Q), клиринговая и ликвидационная цены, сайзинг
market.js      состояние + ДВУХПРОХОДНЫЙ клиринг с обрезкой
npc.js         11 архетипов; 60% реагируют без задержки
orders.js      валидация команд, стопы/тейки/лимиты -> намерения
invariants.js  проверка после каждого тика, HALT при нарушении
snapshot.js    граница клиент/сервер; mark и closeValue раздельно
room.js        цикл тика
test/audit.js  20 приёмочных проверок
```

## Порядок тика

```
1. отложенные (стоп/тейк/лимит)
2. намерения NPC
3. команды людей
4. ОДИН клиринг — единая цена для всех
5. проверка инвариантов; при нарушении HALT с отчётом
```

Люди и NPC на шаге 4 неотличимы.

## Настройки, которые нельзя менять вслепую

- `NPC_INSTANT_FRACTION = 0.60` — доля NPC без задержки реакции. Лаг был
  единственной причиной эксплойта самораскачки: при 0% он давал +0.0385
  (t = 20.7), при 60% EV отрицателен на всех размерах.
- Симметричный сайзинг `units = budget / max(P, PMAX-P)`. Раздельный
  (`budget/P` и `budget/(PMAX-P)`) давал шорту в 1.33 раза больше экспозиции
  за те же деньги → эксплойт «всегда шорт» с 87.8% выигрышей.

Любое изменение — только с перепрогоном `npm test`.
