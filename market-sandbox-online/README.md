# Market Sandbox — как запустить «Онлайн» полностью кликами

Этот гайд не требует ни строчки кода и не требует терминала — только
браузер, GitHub и Google. Займёт минут 20–30 в первый раз.

Если вам нужна только «Практика» (офлайн-режим, один игрок против ботов) —
вам это всё не нужно, возьмите `index.html` и `app.js`, которые уже даны
отдельно, и просто загрузите их на GitHub Pages (см. предыдущее сообщение).
Всё, что ниже, — только для настоящего «Онлайн»-режима с общей комнатой.

## Что мы собираем

Две отдельные вещи:

1. **Firebase** — хранит аккаунты игроков и их баланс. Настраивается
   галочками в веб-консоли, ничего разворачивать не нужно.
2. **Сервис комнат на Cloud Run** — программа, которая крутит рынок и
   ботов 24/7. Её нужно один раз запустить в облаке Google — тоже кликами,
   без установки чего-либо на свой компьютер.

---

## Часть 1. Firebase

### 1.1 Создать проект

1. Откройте [console.firebase.google.com](https://console.firebase.google.com)
2. Нажмите **Create a project** (или «Добавить проект»)
3. Впишите любое название, например `market-sandbox`, нажмите **Continue**
4. Google Analytics — можно выключить переключателем, не нужен. Нажмите
   **Create project**, подождите, нажмите **Continue**.

### 1.2 Включить вход по email и «гостем»

1. В левом меню: **Build → Authentication**
2. Нажмите **Get started**
3. В списке провайдеров нажмите **Email/Password** → включите верхний
   переключатель **Enable** → **Save**
4. Вернитесь в список, нажмите **Anonymous** → включите **Enable** → **Save**

### 1.3 Включить базу данных

1. В левом меню: **Build → Firestore Database**
2. Нажмите **Create database**
3. Выберите любой регион (например `eur3` для Европы) → **Next**
4. Выберите **Start in production mode** → **Create**

### 1.4 Вставить правила доступа

Правила — это то, что не даёт игрокам самим себе дописать деньги на
баланс. Их нужно один раз вставить:

1. Всё там же, в Firestore Database, вверху вкладка **Rules**
2. Сотрите всё, что там есть, и вставьте содержимое файла `firestore.rules`
   из архива (откройте его в блокноте на компьютере, скопируйте весь текст)
3. Нажмите **Publish**

### 1.5 Получить конфиг для сайта

1. Нажмите на шестерёнку рядом с «Project Overview» вверху слева →
   **Project settings**
2. Прокрутите вниз до **Your apps**, нажмите иконку **</>** (Web)
3. Впишите любое имя, **Register app**
4. Появится блок кода с `const firebaseConfig = { ... }` — эти шесть
   строк (`apiKey`, `authDomain`, `projectId`, `storageBucket`,
   `messagingSenderId`, `appId`) вам понадобятся в Части 3. Можно оставить
   эту страницу открытой в соседней вкладке.

---

## Часть 2. Сервис комнат на Cloud Run

### 2.1 Загрузить проект на GitHub

1. Разархивируйте `market-sandbox-online.zip` у себя на компьютере
2. На github.com нажмите **New repository**, назовите его, например,
   `market-sandbox`, **Public**, **Create repository**
3. На странице репозитория — **uploading an existing file**
4. Перетащите **всю папку** `market-sandbox-online` целиком (или все её
   содержимое — папки `packages`, `server`, `app` и файлы `firestore.rules`
   и т.д.) в область загрузки. Современный GitHub сохраняет структуру папок
   при перетаскивании.
5. **Commit changes**

Важно: в этом репозитории должны остаться папки `packages` и `server` —
именно они нужны Cloud Run на следующем шаге.

### 2.2 Развернуть сервис

1. Откройте [console.cloud.google.com](https://console.cloud.google.com)
2. Вверху слева — выбор проекта. Выберите тот же проект, что вы создали
   в Firebase (Firebase-проект — это и есть проект Google Cloud, ничего
   создавать заново не нужно)
3. В поиске сверху введите **Cloud Run**, откройте
4. Нажмите **Create service** (или **Развернуть контейнер → Service**)
5. Выберите **Continuously deploy from a repository (source)** →
   **Set up with Cloud Build**
6. Нажмите **Authenticate** / подключите свой GitHub-аккаунт, если
   попросит, разрешите доступ
7. Выберите репозиторий `market-sandbox` (тот, что загрузили в 2.1),
   ветку `main`
8. Build type: выберите **Dockerfile**. В поле **Source location**
   (путь к Dockerfile) впишите `/server/Dockerfile`
9. Нажмите **Save**
10. Ниже, в основной форме создания сервиса:
    - **Service name**: любое, например `market-sandbox-room-service`
    - **Region**: любой, например `europe-west1`
    - **Authentication**: выберите **Allow unauthenticated invocations**
      (это нормально и безопасно здесь — сервис сам проверяет вход
      каждого игрока по Firebase-токену внутри себя, это не значит,
      что «кто угодно может делать что угодно»)
11. Разверните **Container, Networking, Security** → вкладка
    **Autoscaling**: поставьте и **Minimum number of instances = 1**,
    и **Maximum number of instances = 1**. Это важно — рынок живёт в
    памяти одного запущенного экземпляра, двух одинаковых копий быть
    не должно.
12. Нажмите **Create**

Подождите пару минут, пока соберётся и запустится. Когда закончится,
наверху страницы сервиса будет URL вида
`https://market-sandbox-room-service-xxxxxxxxxx-ew.a.run.app` —
скопируйте его, он понадобится дальше.

### 2.3 Проверить, что сервис жив

Откройте в браузере тот же URL с `/healthz` на конце, например:
`https://market-sandbox-room-service-xxxxxxxxxx-ew.a.run.app/healthz`

Должно показать что-то вроде `{"ok":true,"rooms":0}`. Если видите ошибку —
откройте на странице сервиса вкладку **Logs** и посмотрите, что написано
красным (обычно там прямо сказано, чего не хватает).

## Часть 3. Вписать настройки в сайт

1. Откройте `app.js` (тот, что вы уже выгрузили на GitHub Pages) в любом
   текстовом редакторе — подойдёт даже Блокнот, но удобнее
   [vscode.dev](https://vscode.dev) (открывается в браузере, можно
   редактировать файлы прямо в вашем GitHub-репозитории)
2. Найдите в файле (Ctrl+F / Cmd+F) слово `PASTE_API_KEY_HERE`
3. Замените весь блок:
   ```
   const firebaseConfig = {
     apiKey: "PASTE_API_KEY_HERE",
     authDomain: "PASTE_PROJECT_ID_HERE.firebaseapp.com",
     projectId: "PASTE_PROJECT_ID_HERE",
     storageBucket: "PASTE_PROJECT_ID_HERE.appspot.com",
     messagingSenderId: "PASTE_SENDER_ID_HERE",
     appId: "PASTE_APP_ID_HERE",
   };
   ```
   на те шесть строк, что вы скопировали в шаге 1.5, — просто вставьте
   их значения на место `"PASTE_..._HERE"`, ничего в структуре не трогая.
4. Найдите `PASTE_ROOM_SERVICE_URL_HERE`, замените на URL из шага 2.2,
   например: `const ROOM_SERVICE_URL = "https://market-sandbox-room-service-xxxxxxxxxx-ew.a.run.app";`
5. Сохраните файл и загрузите обратно на GitHub (в тот репозиторий с
   `index.html`, куда включена GitHub Pages) — либо через vscode.dev
   (там есть кнопка «Commit» / публикации прямо в интерфейсе), либо
   через **Add file → Upload files** на github.com, заменив старый `app.js`
6. В `index.html` найдите строку `src="./app.js?v=2"` и увеличьте цифру
   (`?v=3`) — это заставит браузер подхватить новую версию файла, а не
   показывать сохранённую старую

Откройте вашу ссылку на GitHub Pages — выберите «ОНЛАЙН», зарегистрируйтесь
(или войдите как гость). Откройте вторую вкладку в режиме инкогнито и
войдите под другим email — вы увидите второго живого игрока во вкладке
«Участники».

## Если что-то не работает

- **«Firebase не настроен»** — в `app.js` остались значения
  `PASTE_..._HERE`. Проверьте шаг 3.3.
- **Зависает на «подключение к комнате…»** — скорее всего неверный
  `ROOM_SERVICE_URL`, или сервис на Cloud Run ещё не запустился /
  упал. Проверьте `/healthz` (Часть 2.3) и вкладку **Logs** сервиса.
- **«недействительный токен» в логах Cloud Run** — обычно значит, что
  в `app.js` указан Firebase-проект, ОТЛИЧАЮЩИЙСЯ от того, в котором
  запущен Cloud Run. Оба должны быть одним и тем же проектом.
- **После правки app.js в браузере ничего не изменилось** — не забыли
  увеличить `?v=` в `index.html` (шаг 3.6)? Также попробуйте открыть
  сайт в режиме инкогнито — так точно не будет старой сохранённой копии.

## Полезно знать (не обязательно читать, но здесь на всякий случай)

- Комната считает рынок только пока Cloud Run-сервис жив. Если вы его
  остановите (или Google перезапустит по любой причине), рынок начнётся
  заново на следующем зашедшем игроке — прогресс текущих открытых
  позиций не сохранится. Раз в 10 секунд состояние сохраняется в
  Firestore «на всякий случай», но автоматического восстановления при
  перезапуске пока нет.
- Внутри одного сервиса Cloud Run может одновременно крутиться сколько
  угодно комнат (для каждого размера взноса — своя) — ограничение
  «максимум 1 инстанс» не означает «максимум 1 комната».
- Деньги никогда не считаются в браузере игрока — баланс живёт только в
  Firestore и меняется только сервисом на Cloud Run. Даже если кто-то
  откроет консоль разработчика и попробует подделать запрос, сервис
  сам всё проверит и молча откажет.
